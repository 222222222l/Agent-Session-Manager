# 初步整合契约与架构决定

日期：2026-10-03；范围：初步整合，非完整桌面 MVP。

三个完整上游仓库保存在 `upstream/`，保持原代码不修改；固定提交见 `upstreams.lock.json`。运行不依赖这些 checkout。选定上游代码的副本放入 `vendor/`，每个文件有来源和许可证；自有服务位于 `src/`。

## 实际复用边界

- CCHistory：抽取 Claude Code、Codex 和 Gemini 的目录发现／文件匹配模块，通过本项目的小型兼容类型定义使用。保留原文件，Gemini 新 JSONL 不假装被旧 JSON 解析器支持。借鉴其原始证据独立于派生索引的所有权规则，不搬入 UserTurn 中心的完整数据层。
- CC Switch：移植 Gemini JSON 的消息识别、时间／标题处理和 CLI 续接规则。改为保留原消息与诊断、结构化启动参数，不继承删除源文件功能或系统命令字符串执行。
- txcript：直接依赖锁定的 npm WASM 包 0.14.4，真实调用 `toCommon`／`fromCommon`。Rust 源码 checkout 用于比较，npm 发布包能力通过实测确认，不假定与 HEAD 完全一致。

## 本轮交付闭环

显式选择来源 → 只读扫描 Claude／Codex／Gemini JSON → 保存原始字节与版本诊断 → SQLite 统一查询／查看 → 输出续接计划或转换文件包 → 管理库备份、校验、恢复到新目录。提供外部适配器示例，证明新格式无需修改核心枚举或数据库。

CLI 为首个界面，核心接口同时可供后续桌面使用。为尽早运行上游 WASM 并共享 CCHistory 的 TypeScript 片段，本轮采用 TypeScript／Node 22＋SQLite；尚不引入 Tauri／Rust 自有运行时。此前 Tauri 方案仍是后续桌面选项，需要根据真实核心集成成本重新决策，不能声称本轮已有 Rust 桌面。

## 公共边界

Adapter v1 使用字符串 ID、独立版本、发现／匹配／解析／续接计划能力；Core 只接受版本化规范模型及原始证据，不认识特定 Agent 文件结构。txcript 类型被桥接层隔离。新插件为用户显式加载的可信 JS 模块，不声称提供沙箱。

备份覆盖已导入的原始会话文件和管理器元数据，**不覆盖未收集附件、项目代码、外部数据库或原生 IDE 索引**；恢复只进入新的管理库目录。跨 Agent 输出是有损转换文件包，不写入原 Agent 目录、不自动启动 Agent。原生运行续接仅生成带参数数组的计划。

## 验收

通过 CLI 合成样本演练；真实 WASM 转换；未知记录与损坏尾行保留；源文件不变；重复扫描幂等；不同来源同 ID 不冲突；源文件消失不删除归档；篡改备份拒绝；恢复不覆盖现存目录；插件以全新格式导入成功；校验固定上游副本与许可证。运行测试只使用合成数据，不自动扫描个人主目录。
